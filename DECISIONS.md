# Журнал решений

Новые решения добавляются сверху. Формат: дата, решение, почему, источник. Отменённое решение не удаляется, а помечается ссылкой на новое.

## 2026-10-09 — Основная ветка `main`; старые параллельные ветки остаются архивом
- Решение: все изменения идут в `main` через PR. `develop` удалена. PR #1 (`chore/deploy-config`) закрыт. Ветки `codex/feat-order-transparency`, `codex/feat-home-trust`, `codex/feat-postgres-cutover` не вливаются и не удаляются.
- Почему: эти ветки реализуют те же функции, что уже есть в `main`, но с другими колонками в таблицах с теми же именами. Схема создаётся через `CREATE TABLE IF NOT EXISTS`, поэтому их слияние сломало бы существующие базы. Они полезны как справка по Vercel + Neon.
- Источник: решение владельца в сессии 2026-10-09.

## 2026-07-28 — Не продаём выдачу и отклики
- Решение: нет платного ранжирования, продажи места в топ-3, платы за отклик, покупки лидов и скрытой комиссии. Монетизация — комиссия или сервисный сбор только после состоявшегося заказа.
- Почему: отличие от широких площадок и здоровая экономика мастеров.
- Источник: [docs/product/02-product-strategy.md](./docs/product/02-product-strategy.md) («Запрещённые модели»), [docs/product/README.md](./docs/product/README.md), README.

## 2026-07-28 — Текущий runtime — SQLite; PostgreSQL — подготовленный, незавершённый переход
- Решение: активные репозитории работают на `better-sqlite3`. Prisma + PostgreSQL подготовлены, но не являются основным хранилищем, пока не перенесены все сущности и тесты. Постоянный dual-write SQLite/PostgreSQL запрещён. Переход — одна каноническая схема, отрепетированная миграция и явный план отката.
- Почему: MVP разрабатывается локально; частичный перенос без единой схемы приводит к расхождению данных.
- Источник: [AGENTS.md](./AGENTS.md) («Current architecture»), README («База данных и миграции»), [docs/product/README.md](./docs/product/README.md).

## 2026-07-28 — Точный адрес только выбранному мастеру; отзывы только по завершённым заказам
- Решение: адрес клиента скрыт, пока мастер не выбран и не подтвердил заказ. Отзыв нельзя оставить без завершённого заказа.
- Почему: основной контракт доверия продукта.
- Источник: [AGENTS.md](./AGENTS.md) («Product»).

## 2026-07-28 — Интерфейс не выдаёт прототип за работающую функцию
- Решение: демо-маршрут на карте не называется живой геолокацией, платежи считаются внешними до появления PSP с резервом, леджером, возвратом и холдом по спорам. Текст интерфейса, README и release notes разделяют реализованное и запланированное.
- Источник: [AGENTS.md](./AGENTS.md) («Product truthfulness»).

## 2026-07-28 — Порядок P0
- Решение: изменение цены с согласия клиента → обязательные фото до/после → чат заказа → записи гарантии → аналитика воронки без персональных данных → PSP-платежи, живая геолокация и финальный переход на PostgreSQL после юридических и технических решений. Пункты 1–4 реализованы в PR #2.
- Источник: [AGENTS.md](./AGENTS.md) («Current P0 order»), [docs/product/07-p0-specifications.md](./docs/product/07-p0-specifications.md).

## 2026-09-18 — Бренд «Мастер рядом»
- Решение: интерфейс и код используют «Мастер рядом». «МастераТут» — один из вариантов нейминга, не утверждён.
- Источник: [docs/product/06-product-audit-and-smoke-2026-07-30.md](./docs/product/06-product-audit-and-smoke-2026-07-30.md), AGENTS.md.
